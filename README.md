# enterprise-ai-practice

企业 AI 提效的工作方法、平台理念与案例展示。

本仓库面向企业老板、负责人及参与 AI 落地的团队，持续整理如何从真实业务出发，让 AI 承担具体任务，并在共享上下文的基础上逐步参与工作组织与推进。

当前内容包括方法文档与一份 11 页 HTML 展示初稿。企业上下文平台仍处于理念与方案整理阶段，仓库尚未包含该平台的实现代码。

## 核心思路

企业 AI 提效从理解企业如何创造价值、完成交付开始：

**企业目标与交付 → 组织与部门 → 岗位与职责 → 具体任务 → 人机分工 → 持续验证与改进。**

自上而下理解业务后，再选择合适的范围分阶段实施。

具体实践关注两个层面：

1. **让 AI 能完成具体任务。** 将需求整理、资料分析、代码排查等工作沉淀成可复用能力，明确输入、输出和人工判断的边界。
2. **让 AI 理解并衔接工作。** 将目标、项目、职责、流程、规范与反馈组织成共享上下文，结合事件、状态、工具和授权，让 Agent 能够围绕业务持续推进。

平台方向是统一管理企业上下文、业务对象、Skill 和 Agent：同岗位共享规范与工作方法，人员保留各自的项目和个人上下文，实际使用中的改进再回到共享 Skill 中。

## 查看展示稿

将仓库下载到本地后，直接用浏览器打开 `index.html`。页面的 CSS 与 SVG 均内置，无需安装依赖或执行构建。

也可以在仓库目录启动本地静态服务，需要 Python 3：

```bash
python3 -m http.server 8000 --bind 127.0.0.1
```

然后访问 <http://127.0.0.1:8000>。

GitHub 文件页面显示的是 HTML 源码；查看实际排版请使用本地浏览器。

## PDF 排版

展示稿采用 A4 横版，已设置独立分页和打印样式。可通过浏览器打印功能保存为 PDF，建议使用 A4 横向、开启背景图形并关闭浏览器页眉页脚。

当前页面仅用于展示，没有单独的导出按钮。手机浏览时内容会适应屏幕宽度，打印时恢复文档版式。

## 内容状态与维护

- 当前 HTML 中的案例是明确标注的流程演示，不代表真实客户已取得相应成果。
- 个人介绍、联系方式与实际效果数据仍待补充。
- 案例材料区分业务背景、已完成验证、下一阶段设计和预期目标。
- 新增素材先整理并确认事实，再更新展示稿；效果结论以实际记录为依据。
- 后续围绕真实业务持续补充工作方法、案例过程与可核实的交付成果。
